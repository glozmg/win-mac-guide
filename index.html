04 · Everyday

일상 사용에서 체감 큰 설정

키보드와 트랙패드는 기본 설정을 몇 가지 손보면 Windows에서 넘어왔을 때의 이질감이 크게 줄어듭니다.

한

한/영 전환

입력 소스 전환은 기본적으로 Control Space를 쓸 수 있습니다. 설정에 따라 Caps Lock을 한/영 전환용으로 사용하는 것도 가능합니다.

WindowsWin Space
↗

우클릭은 두 손가락

트랙패드의 두 손가락 클릭 또는 Control + 클릭이 Windows 우클릭에 해당합니다. ‘탭하여 클릭’도 설정에서 켤 수 있습니다.

≋

트랙패드 제스처 활용

Mission Control, 데스크톱 전환, 페이지 뒤로/앞으로를 제스처에 맡기면 MacBook 사용성이 훨씬 자연스러워집니다.

⚙

앱 설정은 ⌘ ,

많은 Mac 앱에서 ⌘ ,가 현재 앱의 설정을 여는 관례로 쓰입니다. 메뉴를 찾는 시간을 줄여줍니다.

F

F1~F12를 많이 쓴다면

IDE 디버깅 키를 자주 쓰면 시스템 설정에서 F1~F12를 표준 기능 키로 사용하도록 바꿔두는 편이 편합니다.

⌫

Mac의 Delete는 Backspace 쪽

Mac 키보드의 Delete는 왼쪽 문자를 지웁니다. Windows의 Delete처럼 오른쪽 문자를 지우려면 Fn Delete.

05 · Developer

개발자가 빨리 익히면 좋은 차이

터미널의 Control 키 의미가 크기 때문에 Windows 습관을 무작정 전역 치환하지 않는 게 좋습니다.

I⌁

텍스트 커서 이동

⌥ ←/→는 단어 단위, ⌘ ←/→는 줄 처음/끝입니다. 앞 단어 삭제는 ⌥ Delete.

/

경로로 바로 이동

Finder에서 ⇧ ⌘ G를 누르고 ~/Library, /opt, /usr/local 같은 경로를 바로 입력합니다.

!

먹통 앱 강제 종료

⌥ ⌘ Esc로 강제 종료 창을 엽니다. CPU·메모리까지 보려면 Spotlight에서 “활성 상태 보기”를 실행합니다.

06 · Karabiner-Elements 16.3.0

Windows 키보드 감각은 필요한 만큼만 가져오기

전역 Ctrl↔Command 교환보다 장치별·앱별로 좁혀서 적용하는 구성이 안정적입니다.

추천 프리셋

Windows 개발자라면 이 정도부터

Right Alt→한/영 전환
Caps Tap→Esc
Caps Hold→Control
Home / End→⌘← / ⌘→
Windows VM→Command를 Ctrl처럼
⌨

외장 PC 키보드 배열 보정

Windows 키보드에서 Space 옆 물리 키 감각을 맞추려면 외장 장치에만 Left Alt → Command, Left Windows → Option을 적용합니다.

MacBook 내장 키보드는 그대로 두고 장치별 설정을 권장합니다.
가

Right Alt를 한/영키로

Right Alt 단독 입력을 macOS 입력 소스 전환 단축키로 보내면 Windows 한/영키처럼 쓸 수 있습니다.

CJK 입력 소스는 직접 선택보다 시스템 단축키를 보내는 방식이 공식 문서에서도 권장됩니다.
⇪

Caps Lock을 Tap / Hold로 분리

짧게 누르면 Esc, 누른 채 다른 키를 쓰면 Control로 설정할 수 있습니다. Vim·터미널 사용자에게 특히 유용합니다.

Caps TapEscCaps HoldControl
H

Caps를 Hyper 레이어로

⌘⌥⌃⇧ 조합을 Hyper로 만들어 Caps H/J/K/L에 방향키, 앱 실행, 창 이동 등을 배치할 수 있습니다.

H←J↓K↑L→
⇤

Home / End를 Windows식으로

풀사이즈 키보드의 Home을 ⌘ ←, End를 ⌘ →로 보내면 Windows 편집 습관을 상당 부분 유지할 수 있습니다.

◫

Ctrl 단축키는 앱별로만

GUI 앱에서만 Ctrl C → ⌘ C처럼 바꾸고 Terminal에서는 원래 Control을 유지할 수 있습니다.

개발자는 Ctrl+C, Ctrl+D, Ctrl+Z가 터미널 의미를 가지므로 전역 Ctrl→Command는 비추천입니다.
▣

Windows VM / RDP에서만 키 교환

Parallels·VMware·Windows 원격 앱이 앞에 있을 때만 Command를 Control로 바꾸면 복사/붙여넣기 근육 기억을 유지하기 쉽습니다.

⌁

EventViewer로 실제 입력 확인

특수키·한/영키·마우스 버튼이 실제로 어떤 key code를 보내는지 확인합니다. 장치의 Vendor/Product ID와 앱 Bundle ID 확인에도 씁니다.

P

프로필 분리

Development / Windows Remote / Gaming처럼 프로필을 나누면 상황별 remap을 깔끔하게 관리할 수 있습니다.

◁

마우스 측면 버튼

지원되는 pointing device 이벤트라면 Button 4/5를 뒤로·앞으로 같은 동작에 연결할 수 있습니다.

Fn

외장 키보드 Fn 주의

일부 비 Apple 키보드는 Fn을 하드웨어 내부에서 처리해 macOS에 이벤트를 보내지 않습니다. 이 경우 Karabiner도 Fn 자체를 remap할 수 없습니다.

추천
  • 외장 키보드에만 배열 보정
  • Right Alt → 한/영
  • Caps Tap/Hold 또는 Hyper
  • VM·RDP처럼 앱 범위를 좁힌 remap
피하는 편이 좋은 것
  • 전역 Ctrl ↔ Command 교환
  • IDE keymap과 Karabiner 중복 remap
  • 외장 키보드 Fn이 항상 감지될 것이라는 가정
